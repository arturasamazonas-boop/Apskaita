# Testing

All tests run against a real PostgreSQL 16 database. They drop and recreate the dedicated test database `apskaita_test`; never point them at real data. They use real system tools (poppler, Tesseract 5 `lit+eng`, ImageMagick, xmllint) and the committed fixtures in `fixtures/` (fictional companies, regenerated by `npm run fixtures`).

| Command | What it does |
|---|---|
| `npm run check` | `node --check` on all JS modules, `php -l` on the OpenCart extension |
| `npm test` | 51 `node:test` tests across 11 files |
| `npm run test:browser` | Chromium (Playwright) UI smoke test of the real UI and server |
| `npm run perf` | 10,000-document timings ([PERFORMANCE.md](PERFORMANCE.md)) |

## Chart of accounts, products and stock, payroll (`10-chart-products-payroll`)

| Area | What the test checks |
|---|---|
| Chart | Tree imported from the workbook. Posting roles. Pickers list leaf accounts only. Posting to a group is rejected by the API and by a raw insert (DB trigger). A sub-account turns an unused leaf into a group. A used account cannot be split. Sub-account codes must start with the parent code. |
| Upgrade | A database migrated to 008 with postings on old starter accounts is upgraded. Used accounts are deactivated and keep their postings; unused ones are removed. Bank accounts are repointed. |
| Products | All card fields are saved. SKU is unique. A group account is refused. Stock comes from opening balance, write-off (reason required), and an approved purchase and sale linked to the product. Also checked: totals, weighted average cost, balance on a date, the movement list with running balance, immutability of movements, low-stock filter, partial update, and services without stock. |
| Payroll calculation | 2026 NPD formula, GPM, VSD/PSD, employer Sodra. Net pay at 2000 € and at MMA. NPD phase-out and cap. Fixed NPD. Pro-rata days, extra pension and the fixed-term employer rate. Hourly pay. The working-day norm with holidays. |
| Payroll sheet | Employees. A masked personal code for read-only users. Sheet creation with the norm and pro-rata start. Editing bonus and advance. One sheet per month. Read-only cannot approve. Approval posts the expected amounts to 6304/6203, 4480, 4481 and 4482. Double approval posts once. An approved sheet is read-only. The journal source link. Cancel by reversal, re-approval with a new entry, and no deletion after approval. |

## Other checks

- **Malicious instructions** inside an invoice stay inert text (`01`, last test); LLM output schema and allowlist filtering.
- **Rounding:** exact decimals, half-up, per-line VAT tolerance, allocation sums (`00-unit`).
- **Concurrent numbering:** 8 parallel approvals produce gap-free unique numbers (`04`).
- **Provider failure and retry:** a corrupt PDF is retried 5 times, then marked failed with an actionable message, then manually retried; a transient failure is retried successfully; idempotent enqueue (`04`).
- **Re-extraction** of a posted document leaves it unchanged; the correction posts only the delta (`04`).
- **Extraction fixtures** cover native PDF, DOCX tables, a scanned PDF with a smudged amount, a skewed phone photo (JPG), a 90°-rotated scan (PNG, OSD), a 2-page 42-line invoice, two invoices in one file, a proforma, a credit note, a sales invoice, and a legacy `.doc` (rejected with an explanation).
- **Integrations:** Saleor via a mock GraphQL/JWKS server with real JWS signatures; OpenCart via the real extension under `php -S`; webhook duplicates, out-of-order delivery, 429 retry and resume, demo labelling (`05`).
- **Database and file backup** → restore → verification → app restart on the restored copy (`07`).
- **Container:** the Docker image was built and run with docker compose (PostgreSQL 16 + app). Admin creation, login, upload and OCR of the scanned invoice inside the container, and the i.SAF XSD check were all exercised manually with a script.

## Not verified

- No live Saleor or OpenCart store was used; integration tests are fixture/mock tests. See the live checklist in [INTEGRATIONS.md](INTEGRATIONS.md).
- The vendored i.SAF XSD was not compared with the file on vmi.lt (blocked); see [ISAF.md](ISAF.md).
- The optional Anthropic LLM provider was not called (no credentials). Only its output validation is tested.
- No ClamAV scanning (not installed).
- No restore onto a different host; no load testing with concurrent users.
- Accessibility was checked only through semantic markup, keyboard focus styles and the browser test's role-based selectors. No screen-reader audit was done.
